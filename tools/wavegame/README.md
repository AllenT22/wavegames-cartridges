# Wave Games cartridge developer tools

This directory is the dependency-free reference toolkit for Cartridge API 1.
It requires Node.js 24 or newer and uses only Node built-ins.

## Commands

```text
node tools/wavegame/bin/wavegame.mjs create my-game \
  --id games.example.my-game --title "My Game"
node tools/wavegame/bin/wavegame.mjs validate my-game
node tools/wavegame/bin/wavegame.mjs test my-game
node tools/wavegame/bin/wavegame.mjs pack my-game my-game.wavegame
node tools/wavegame/bin/wavegame.mjs inspect my-game.wavegame
node tools/wavegame/bin/wavegame.mjs dev my-game
```

The repository's reproducible first-party release command is:

```text
node tools/wavegame/bin/build-first-party.mjs [output-directory]
```

It tests, packs, reads back, and digest-verifies Connect Four, Checkers, Chess,
Go, and Color Match before producing individual import files plus a source-and-toolkit
bundle for public, unsigned distribution. It refuses to replace an existing
output directory.

`dev` is the short developer-loop name for `simulate`; both commands start the
same local multi-seat simulator.

`create` produces a self-contained cartridge with rules, UI, its embedded API
client, an icon, and a runnable scenario. `test` executes the authority rules
and optional scenarios from a trusted source directory in Node; it never
executes a downloaded `.wavegame` archive or cartridge UI. Developer source is
still code with the developer's account privileges, so review it before
running `test` or `dev`. `simulate` serves the package on
localhost and renders one sandboxed frame for each selected seat, from one
through eight where the manifest allows it.

`pack` is deterministic: unchanged input bytes produce identical `.wavegame`
bytes. It writes a stored ZIP with normalized timestamps and permissions. A
package is never overwritten implicitly.

## Cartridge layout

```text
wavegame.json
rules/index.mjs
ui/index.html
ui/game.mjs
ui/wavegames-sdk.mjs
assets/icon.svg
tests/scenarios.mjs
META-INF/files.json       generated by pack
```

`wavegame.json` follows
[`schema/wavegame-manifest.schema.json`](schema/wavegame-manifest.schema.json).
The app's Dart model is the canonical API 1 contract. In particular:

- `formatVersion` and `engineApi` are both `1`.
- Reverse-domain IDs are lowercase and at most 48 characters so WCP1 lobby
  metadata remains within one WaveWire payload.
- `icon`, rules, and UI entrypoints are required relative package paths. API 1
  paths use portable ASCII letters, digits, dots, underscores, and hyphens so
  the same package cannot alias different files on Android, iOS, or macOS.
- Capabilities are limited to `storage` and `audio`.
- Local mode permits 1–8 players. Wave mode permits 2–8 players and must be
  `turn-based`.
- Every payload file, including `wavegame.json`, is listed by UTF-8 path order
  in `META-INF/files.json`. The index does not list itself.
- Package identity is SHA-256 of the exact canonical index bytes. It identifies
  exact content; it is not a publisher signature.

The cross-language canonicalization vector is in `testdata/`. Dart and Node
must produce the digest in `package-index-v1.sha256` from
`package-index-v1.json` before either implementation changes the format.

## Rules contract

The rules module is separate from rendering and exports:

```js
export function create({ seed, players, options, random }) { /* JSON state */ }
export function reduce({ state, playerId, action, revision, requestId, random }) {
  return { accepted: true, state, events: [] };
  // or { accepted: false, reason: '...' }
}
export function view({ state, viewer, players, revision }) { /* filtered JSON */ }
```

State is authoritative and is never sent directly to a UI. `view()` must return
only information safe for its `viewer`. The simulator clones every boundary,
serializes actions through one authority queue, restores deterministic random
state after rejected actions, and enforces the API byte limits. `create()` and
accepted `reduce()` calls consume one shared host-owned random stream. Both the
browser simulator and `wavegame test` install the same rules guard before game
modules load: implicit wall clocks, ambient entropy, timers, persistent browser
storage, and `Math.random()` fail, while explicit dates such as `new Date(0)`,
`Date.parse()`, and `Date.UTC()` remain available. A rules module
may additionally export `conformanceActions({players, state})`; `wavegame test`
replays that bounded action trace twice and compares every result and authority
state to catch nondeterministic reductions.

Presentation `events` are delivered in local play and the simulator. Nearby
API 1 deliberately transports only filtered views; derive nearby presentation
cues from successive views so private rule details cannot leak to every seat.

Optional `tests/scenarios.mjs` exports `scenarios`, an array of `{name, players,
seed?, run({host, players, assert})}` records. Scenarios use the same simulation
host as the browser.

## UI bridge

Cartridge UI imports its bundled client relatively:

```js
import { WaveGames } from './wavegames-sdk.mjs';
const game = await WaveGames.connect({ api: 1 });
game.onView((view, revision) => render(view));
await game.sendAction({ type: 'move', cell: 4 });
```

The returned session supplies `context`, optional current `view`,
`sendAction()`, `onView()`, `onRoster()`, `onStatus()`, optional `onEvent()`, and
`storage.get/set/remove()`.

The bundled client supports both hosts without changing game code:

1. The browser simulator completes a `wavegames:client-ready` /
   `wavegames:attach` MessagePort handshake with the cartridge frame.
2. The mobile host installs `window.WaveGames = {connect}` before cartridge
   modules execute and dispatches
   `window.dispatchEvent(new Event('wavegames:runtime-ready'))`.

The bundled client never writes `window.WaveGames`, so it cannot replace the
mobile runtime.

## Package safety

Both packer and reader enforce the 25 MiB archive, 75 MiB expanded, 1,000-entry,
and 20 MiB per-file limits. The reader validates CRC-32, declared sizes, local
and central metadata, UTF-8 paths, case collisions, encryption, symlinks,
unsupported compression, ZIP64, overlapping/hidden data, and unsafe expansion
ratios before returning package files. Files are hashed with SHA-256 and must
exactly match the generated index.
